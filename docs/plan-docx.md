# DOCX 查看与轻量编辑 —— 开发方案与技术难点分析

> 目标：像现在的 Excel 表格模块一样，把 `.docx` 做成「打开即看、顺手能改、改完可控写回」的一等公民，并**自动处理亿赛通等透明加密文档**。
> 定位延续项目既有原则：**简单查看编辑**，不追求像素级排版还原，不做样式设计器。

---

## 〇、范围已定（2026-09-29 确认）

| 决定 | 内容 |
| --- | --- |
| **DOCX 只做查看，不做编辑** | 目标是"看得清、看得快、能复制"，编辑交给 Word / WPS |
| **允许复制内容** | 文字可选中复制；另提供「复制全部文本」与「复制表格为制表符文本」（可直接粘进 Excel） |
| **自动解密** | 打开即内存解密（复用 `esafenet::decrypt_esafenet`），不落明文临时文件 |
| **需要编辑时调用外部应用** | 工具栏「打开方式」→ 系统默认程序 / 「选择其它应用…」（Windows 打开方式对话框）；**传原始路径**，加密文档由系统驱动在目标程序里透明解密 |
| **Excel / CSV 同样加上「打开方式」** | 已实现（见下） |

> 因此原方案里的**编辑、写回、表格编辑等阶段全部移出范围**；下文的"写回策略"保留作背景资料，供将来真要编辑时参考。

### 已实现：调用本地其它应用打开（0.20.6）

- Rust 命令 `open_with_app(path, mode)`：`mode = "default"` 用系统默认关联程序（`ShellExecuteW` 的 `open` 动词），`mode = "choose"` 弹出系统「打开方式」对话框（`openas` 动词）；先校验文件存在并给出中文错误（找不到关联程序 / 被安全软件拦截等）
- 前端 `openActiveDocWithExternalApp(mode)`：有未保存改动时先提示"外部应用打开的是磁盘上的版本"
- 入口：工具栏 **「打开方式」** 下拉、标签右键 **「选择其它应用打开…」**
- **对任何已保存到磁盘的文档都可用**（Excel / CSV / PDF / Markdown，以及将来的 docx）

## 一、先说结论：三件事已经免费，一件是真正的大山

| 能力 | 现状 | 结论 |
| --- | --- | --- |
| **自动解密 / 加密回写** | `src-tauri/src/commands/esafenet.rs` 已有 `is_esafenet_encrypted` / `decrypt_esafenet` / **`encrypt_esafenet(header, plaintext)`** | ✅ **已解决**：解密读、加密写都能直接复用，docx 与 xlsx 走同一条路 |
| **延迟写回 + 原子保存** | 表格模块的 `office_write::save_pipeline`（临时文件 → 校验可读 → `fs::rename`） | ✅ **可复用**：docx 只是把"工作簿"换成"文档 XML 包" |
| **撤销栈 + 影子文档** | `office_shadow.rs`（内存影子 + 快照栈 30 步 / 512MB） | ✅ **模式可复用**：换成文档级快照即可 |
| **排版还原** | 无 | ⚠️ **真正的大山**：DOCX 是**流式排版**格式，像素级还原需要自己实现断行、分页、表格布局、浮动对象 —— 这是几个月量级的工作，本方案**明确不做** |

## 二、渲染策略：结构忠实，而非像素忠实

### 三个选项与取舍

| 方案 | 效果 | 成本 | 结论 |
| --- | --- | --- | --- |
| A. 像素级分页还原 | 与 Word 一模一样 | 需自研排版引擎（断行/分页/表格布局/浮动图/避头尾），数月且永远追不平 | ❌ 不做 |
| B. **结构忠实流式视图** | 段落、表格、图片、字体字号颜色、加粗斜体下划线、对齐缩进、项目符号**都对**；不强制分页 | 复用虚拟滚动 + HTML/CSS 排版，可控 | ✅ **采用** |
| C. 外部转换（LibreOffice 无头模式转 HTML/PDF） | 还原度高 | 需要额外分发上百 MB 的运行时，与"6.5 MB 安装包"的定位直接冲突 | ❌ 不做 |

### 方案 B 的具体形态

- **块级模型**：把文档解析成有序块 —— 段落 / 表格 / 图片 / 分页符 / 分隔线，每块带自己的排版属性
- **不强行分页**，但在分节符处画一条**淡色"分页提示线"**（知道原来在哪分页，又不必自己排版）
- **表格**：真实 `<table>` 渲染，支持合并单元格（`gridSpan` / `vMerge`）、列宽、边框、单元格内多段落
- **样式继承链**要解析：`docDefaults → 段落/字符样式 → basedOn 继承 → 直接格式`（否则字号字体会错，这是"看起来不像"的最常见原因）
- **列表编号**：解析 `numbering.xml`，把 `numId/ilvl` 还原成项目符号或有序编号（含多级）
- **图片**：从 zip 里按需取出，走已有的 asset 协议显示；不认识的嵌入对象（OLE/图表）显示占位卡片而不是报错
- **中文字体**：按文档里的字体名渲染，缺失时回退到系统字体链；不做字体嵌入（授权问题）

## 三、编辑策略：段落级结构化编辑，坚决不用 contentEditable

### 为什么不能用 contentEditable

浏览器会把用户操作变成任意 HTML（嵌套 `<span>`、`<b>`/`<strong>` 混用、粘贴带来一堆内联样式），**再映射回 OOXML 是有损且不可预测的** —— 保存后 Word 里样式乱掉、甚至文档损坏。这是同类工具翻车的经典原因。

### 采用：块级编辑器 + run 保留算法

- **每个段落是一个编辑单元**（文本框式），表格单元格内也是段落编辑单元
- **改文字时保留格式**：段落内部由若干 run 组成（每个 run 有自己的加粗/字号/颜色），编辑后按下面的规则重映射：
  - 新插入的字符**继承插入点前一个字符所属 run 的格式**（与 Word 一致）
  - 删除跨越多个 run 时，从被删区间两端的 run 里精确扣除字符数，空的 run 丢弃
  - 只改文字、不改结构时，**其余 XML 节点（书签、批注锚点、域代码、修订标记）原样保留** —— 通过"只改 `<w:t>` 文本节点"实现
- **v1 的格式操作作用在整段**（加粗 / 斜体 / 下划线 / 对齐 / 列表级别），**v2 再做字符级选区格式**（需要自建选区模型，成本明显更高）

## 四、写回策略：外科手术式 XML 改写（安全性的核心）

**不做整包重写。** 与 xlsx 用 umya 整体重建不同，docx 包里有大量"我们不认识但 Word 需要"的东西：`styles.xml`、`numbering.xml`、主题、关系、批注、页眉页脚、customXml、嵌入对象……

```
原 docx（zip）
├── [Content_Types].xml        原样复制
├── word/document.xml          ← 只改这一个（且只改我们动过的节点）
├── word/styles.xml            原样复制（除非用户改了样式）
├── word/numbering.xml         原样复制
├── word/media/*               原样复制
└── 其它所有部件                原样复制（字节级不变）
```

- **未编辑的部件字节级不变**，重新打包时沿用原压缩参数
- **无操作不变式**：打开后直接保存（不做任何修改）→ 输出必须能被 Word/WPS 正常打开，且除 zip 元数据外内容一致 —— 这条作为**验收红线**，用测试语料批量验证
- **保存流程**沿用表格模块：临时文件 → 用解析器回读校验 → 原子替换；`.bak` 默认关闭（与表格一致，可在设置开启）
- **加密文档**：源文件是亿赛通加密的 → 保存时用**同一个 header 重新加密**后写回（`encrypt_esafenet` 已有）

## 五、架构落点（与现有模块一一对应）

### Rust 侧（新增 4 个文件，复用 3 个）

| 新文件 | 职责 | 可复用的既有实现 |
| --- | --- | --- |
| `commands/office_docx.rs` | 读：zip + XML → 结构化块模型（含样式继承、编号、表格、图片索引） | `esafenet::*`（解密）、`describe_parse_failure`（打不开的提示话术） |
| `commands/office_docx_write.rs` | 写：外科手术式改 `document.xml` + 重新打包 + 加密回写 | `office_write::save_pipeline` 的原子替换思路 |
| `commands/office_docx_shadow.rs` | 内存影子文档 + 快照栈（撤销/重做） | `office_shadow.rs` 的整套模式 |
| `commands/office_docx_ops.rs` | 查找、统计、段落增删、表格增删行列 | `office_ops.rs` 的窗口化返回 |

**命令契约**（与表格模块保持同构，前端好接）：

```rust
document_info(path)      -> { sheets? 不适用; sections, blocks_total, encrypted, editable }
document_blocks(path, from, count) -> 窗口化的块（虚拟滚动用）
document_find(path, query, options) -> 命中（段落/表格单元格定位）
document_state(path)     -> { pending, canUndo, canRedo }
document_save(path, edits) -> 写回（含加密）
document_undo / redo / discard
```

**新增依赖**：`zip`（读写包，或用 umya 内部已有的版本保持统一）、`quick-xml`（流式解析与**定点改写**）。
> 不建议直接上 `docx-rs` 做写回：它擅长"从零生成"，而我们需要的是"**在原文件上动最少的地方**"，两者目标相反。可以只借它的类型定义做参考。

### 前端侧（新增目录 `src/components/Docx/`）

| 文件 | 职责 |

| `DocxBlock.tsx` | 单块渲染（段落/图片/分页提示），编辑态切换 |

## 六、技术难点分级（按"会不会卡住项目"排序）

### 🔴 一级难点（决定成败）

1. **写回安全 —— 一个字节都不能弄丢**
   DOCX 的复杂度不在"读"，而在"改完还得让 Word 认"。任何整包重建都可能丢掉不认识的部件。**缓解**：外科手术式改写 + 未动部件字节级不变 + 无操作不变式红线 + 测试语料批量回归 + 保存前回读校验。

2. **排版还原的期望管理**
   用户会拿它和 Word 比。表格列宽、浮动图片环绕、分栏、文本框、数学公式（OMML）都做不到像素级。**缓解**：明确"结构忠实"定位、对不支持的对象**显示占位卡片并说明**（而不是静默丢失或报错）、在首次打开复杂文档时给一次性提示。

3. **run 与文本的双向映射**
   段落内多 run、书签/批注锚点/域代码穿插其中，删除与插入跨 run 时的格式归属很容易出错。**缓解**：把"只改 `<w:t>`、不动其它节点"作为铁律；run 切分/合并写成独立纯函数并配大量单测（可用表格模块 `sheetReplace` 的思路：先纯函数、再接线）。

### 🟡 二级难点（有工作量，但路径清晰）

4. **样式继承链**：`docDefaults → 样式 → basedOn → 直接格式`，字号字体颜色对齐缩进全部要逐级解析，否则"看起来不像"
5. **表格**：合并单元格（`gridSpan`/`vMerge`）、嵌套表格、边框与底纹、单元格内多段落 —— 视觉最复杂的一块
6. **编号与多级列表**：`numbering.xml` 的抽象编号与层级覆盖，还原项目符号/编号
7. **虚拟滚动 + 高度测量**：段落高度依赖换行，块高度得测（表格网格已有"按字体逐字测量取上界"的成熟做法可搬）
8. **撤销粒度**：一次连续输入应合并成一步（表格模块的"拖动只记一步"已经踩过这个坑）
9. **测试体系**：需要一份 **docx 语料库**（简单文本 / 多级列表 / 复杂表格 / 图片 / 中文特殊字体 / 页眉页脚 / 修订痕迹 / 加密 / 超大文档 / WPS 生成），并对每个文件跑"打开→保存→回读→Word 打开"回归

### 🟢 三级难点（顺手就做了）

10. **自动解密**：解密与加密 API 都现成，接上即可（真正的风险只在"写回时必须加密"，漏了就会把密文文档写成明文 —— 需要一条专门的断言守住）
11. **docType 接线**：涉及文件多但都是机械改动
12. **查找与统计**：文档模型是线性的，比表格的二维定位更简单
13. **图片显示**：asset 协议已启用，按需从 zip 取图即可

### ⛔ 明确不做（写进文档与界面提示）

- `.doc`（97-2003 二进制格式）：解析库不支持，明确提示"请用 Word 另存为 .docx"
- `.docm`（含宏）：只读查看，不写回
- 修订痕迹（track changes）：只**显示**最终态，不提供接受/拒绝
- 域代码与目录自动更新、OMML 公式编辑、SmartArt/图表、OLE 嵌入对象、文本框与浮动排版
- 样式设计器（新建/修改样式、主题配色）

## 七、落地路线图（只读查看，一次交付）

### 0.21.0 —— DOCX 只读查看

**Rust 侧**
1. `commands/office_docx.rs`：zip 解包 + `quick-xml` 流式解析 `word/document.xml`
   - 块模型：段落 / 表格 / 图片 / 分页符 / 分隔线，每块带排版属性
   - 解析样式继承链（`docDefaults → 样式 → basedOn → 直接格式`）得到最终字体、字号、颜色、粗斜体、下划线、对齐、缩进、行距
   - 解析 `numbering.xml`，把 `numId/ilvl` 还原成项目符号 / 有序编号（含多级）
   - 图片从 `word/media/` 按需取出（走已有 asset 协议）
   - 不认识的节点（SmartArt、OLE、文本框、OMML 公式）→ **占位块 + 类型说明**，绝不静默丢失
2. 命令：`document_info(path)`、`document_blocks(path, from, count)`（窗口化）、`document_find(path, query)`
3. 解密：入口统一走 `read_document_bytes`（内部先 `is_esafenet_encrypted` → `decrypt_esafenet`）
4. 打不开时沿用 `describe_parse_failure` 的话术（需要密码 / 旧版 `.doc` / 假 docx / 加密软件处理过）

**前端侧**（`src/components/Docx/`）
5. `DocxView.tsx` 容器（内容栏、查找面板、缩放、工具栏联动）
6. `DocxBlocks.tsx` 虚拟滚动块列表（复用表格网格"只渲染可见窗口 + 高度索引"的经验；段落高度按字体测量取上界）
7. `DocxBlock.tsx` / `DocxTable.tsx`：段落与表格渲染；**文字默认可选中复制**
8. 复制增强：`Ctrl+C` 复制选区、右键「复制全部文本」、表格右键「复制为制表符文本」
9. 视图三态：`preview` = 文档视图、`source` = 原始 `document.xml`（高级用户偶尔要看）、`split` = 左右对照
10. 大纲侧栏：按标题级别生成目录，点击跳转
11. 会话恢复：记住滚动位置与视图模式

**接线改动**：`docType` 增加 `"document"`、`DocKind` 增加 `"document"`、`DOCUMENT_EXTENSIONS = [".docx"]`、文件分发与状态栏、`useAutoSave` 跳过（与表格一致）、**不加入 `fileAssociations`**（沿用不劫持默认程序的约定）

**验收标准**
- 语料库（简单文本 / 多级列表 / 复杂表格 / 图片 / 中文特殊字体 / 页眉页脚 / 修订痕迹 / 加密 / 超大 / WPS 生成）**全部能打开且不崩**
- 未支持对象显示占位说明而不是空白或报错
- 200 页文档滚动流畅（虚拟滚动生效）
- 加密文档打开即解密、状态栏显示「已解密」
- 文字可选中复制；表格可复制成制表符文本粘进 Excel
- 只读：`Ctrl+S` 不写盘；「打开方式」可交给 Word / WPS 编辑

**不做**：编辑与写回、表格编辑、修订痕迹接受/拒绝、域与目录更新、OMML 公式、SmartArt/图表/OLE、`.doc` 老格式（明确提示"请另存为 .docx"）、`.docm` 写回

## 九、一句话总结

> **"自动解密"和"延迟写回"这两件最难的事，项目里已经做完了**（表格模块已经跑通解密读、加密写、影子撤销、原子保存）。
> docx 只读查看的真正难点只有两个：**排版还原的期望管理**（用"结构忠实 + 占位提示"化解）与 **解析的完备性**（用测试语料库 + 占位兜底化解）。
> 不需要写回，就没有"一个字节都不能丢"的风险 —— 这让 0.21.0 成为一个**低风险、可一次交付**的版本。
